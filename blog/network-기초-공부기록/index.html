Network 기초

웹 접근 제어 시스템을 만들기 위해서는 요청이 네트워크 안에서 어떻게 이동하는지 이해해야 한다.

이번 공부에서는 IP 주소, subnet mask, gateway, DNS, switch, router의 역할을 중심으로 정리했다.

IP 주소와 네트워크 대역

IP 주소는 장비를 구분하는 논리적 주소다.

IP 주소는 크게 두 부분으로 볼 수 있다.

text
네트워크 부분 + 호스트 부분

예를 들어 192.168.111.100/24에서:

  • 192.168.111은 네트워크 대역
  • 100은 호스트 주소

같은 네트워크 대역에 있는 장비끼리는 라우터를 거치지 않고 통신할 수 있다.

Subnet Mask

Subnet mask는 IP 주소에서 어디까지가 네트워크 부분인지 알려준다.

예시:

text
IP: 192.168.111.100
SM: 255.255.255.0

이 경우 192.168.111.0/24 대역으로 볼 수 있다.

Gateway

Gateway는 다른 네트워크로 나갈 때 사용하는 출입구다.

같은 네트워크 대역 안에서는 gateway가 필요하지 않지만, 외부 네트워크로 나가려면 gateway를 거쳐야 한다.

예시:

text
IP: 192.168.111.100
SM: 255.255.255.0
GW: 192.168.111.1
DNS: 168.126.63.1

Switch와 Router

Switch는 같은 네트워크 안의 장비들을 연결한다.

Switch는 MAC address table을 보고 목적지 장비를 찾는다.

Router는 서로 다른 네트워크를 연결한다.

text
같은 대역: PC → Switch → PC
다른 대역: PC → Switch → Router → 다른 네트워크

DNS

DNS는 도메인 이름을 IP 주소로 바꿔준다.

사용자가 example.com에 접속하면 실제 통신은 IP 주소를 기준으로 진행된다.

웹 차단 시스템에서는 DNS와 도메인 구조를 이해하는 것이 중요하다.

  • 도메인 기준 차단
  • URL 기준 차단
  • IP 기준 차단
  • DNS 응답 기준 탐지

이 네 가지는 서로 다른 방식으로 동작한다.

tcpdump로 요청 확인

패킷이 실제로 지나가는지 확인할 때는 tcpdump를 사용할 수 있다.

bash
sudo tcpdump -i enp0s3 port 80

확인할 수 있는 것:

  • 요청이 실제로 발생했는지
  • 어떤 IP로 나가는지
  • 어떤 port를 사용하는지
  • 차단 전후 흐름이 달라지는지

프로젝트와 연결되는 부분

AI 웹접근제어 보안 솔루션에서는 네트워크 지식이 다음 부분과 연결된다.

  • 사용자의 웹 요청 흐름 이해
  • 차단 위치 결정
  • 패킷 확인
  • gateway와 DNS 설정 이해
  • 정책 적용 전후 통신 확인

네트워크 공부의 핵심은 명령어보다 데이터가 어디서 어디로 이동하는지 흐름을 보는 것이다.
