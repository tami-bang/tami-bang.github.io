# QA Guide Automation - Public Work Sample

## 2개월 QA 인턴 활동 기록

지란지교에서 2개월간 QA 인턴으로 근무하며 테스트 수행, 이슈 재현,
결과 기록과 함께 반복 업무를 개선하는 프로젝트를 진행했습니다.

짧은 인턴 기간을 단순한 업무 체험으로 보내기보다, 매일 수행하는
업무에서 반복되는 불편을 관찰하고 다음 업무와 다음 사람이 더 수월해질
수 있는 결과물을 남기는 것을 목표로 삼았습니다.

그 결과 테스트 가이드 자동화, 화면 네비게이션, 신입 사용자용 스타터
키트를 제작했습니다. 이 저장소는 해당 결과물의 설계와 핵심 로직을 외부
공개가 가능한 형태로 재구성한 샘플입니다.

회사 내부 URL, 제품명, 티켓, 고객사, 화면 경로, 인증정보는 포함하지
않습니다. 실제 업무에서 사용한 핵심 설계인 요구사항 파싱, 테스트
시나리오 생성, 사용자 문서 보호 로직을 작은 실행 예제로 재현했습니다.

## 활동 목표

- 보안 소프트웨어의 클라이언트, 관리자 페이지, 정책, 로그 연결 구조 이해
- 이슈를 재현 가능한 조건과 기대 결과로 정리하는 QA 기본기 습득
- 반복 업무를 발견하고 실제 사용할 수 있는 자동화와 문서로 개선
- 인턴 이후에도 참고하고 확장할 수 있는 형태로 결과물 정리

## 발견한 반복 문제

- 이슈 설명을 읽고 테스트 목적과 시나리오를 문서에 반복해서 옮겨야 했습니다.
- 화면 경로와 정책 확인 위치가 흩어져 있어 같은 내용을 다시 찾아야 했습니다.
- 자동 작성 기능이 기존 사용자 내용을 덮어쓰지 않도록 보호 장치가 필요했습니다.

## 2개월간의 진행 과정

### 1. Learn - 제품과 QA 흐름 이해

화면, 정책, 로그의 연결 관계를 따라가며 테스트를 수행했습니다. 이슈를
재현할 때에는 조건, 기대 결과, 실제 결과와 증거를 분리해 기록했습니다.

### 2. Observe - 반복되는 불편 발견

테스트 문서 초안 작성과 화면 경로 탐색이 반복되고, 업무 지식이 여러
문서와 화면에 흩어져 있다는 점을 개선 대상으로 정의했습니다.

### 3. Build - 자동화 도구와 가이드 구현

Jira와 Notion을 연결한 테스트 가이드 자동화, 사용자 문서를 보호하는
템플릿 가드, 업무 목적별 화면 네비게이션, 설치 및 연결 스타터 키트를
구현했습니다.

### 4. Share - 재사용 가능한 결과물로 정리

코드만 남기지 않고 실행 방법, 보안 원칙, 오류 대응, 검증 테스트를 함께
정리했습니다. 다른 사용자가 작업을 이어갈 수 있는 형태를 기준으로
결과물을 구성했습니다.

## 자동화 흐름

```text
이슈 데이터
  -> 요구사항 및 메타데이터 파싱
  -> 키워드 기반 QA 범위 선택
  -> 테스트 시나리오 초안 생성
  -> 템플릿 상태 및 사용자 작성 흔적 검증
  -> Dry-run 확인
  -> 문서 반영
```

## 공개 샘플 구성

```text
qa-guide-automation/
├── README.md
├── package.json
├── docs/
│   └── screen-navigation-sample.md
├── src/
│   ├── issue-parser.js
│   └── template-guard.js
└── test/
    └── automation.test.js
```

- `issue-parser.js`: 이슈 요약과 설명에서 테스트 대상 및 시나리오를 생성합니다.
- `template-guard.js`: 사용자 작성 흔적과 완료 마커를 검사해 자동 수정을 차단합니다.
- `screen-navigation-sample.md`: 화면 경로 목록을 업무 목적별 질문으로 바꾼 문서 샘플입니다.
- `automation.test.js`: 파싱 및 보호 로직의 핵심 동작을 검증합니다.

## 실행

Node.js 18 이상에서 외부 패키지 없이 실행할 수 있습니다.

```bash
npm test
```

## 실제 업무 구현 범위

- Jira REST API와 Notion API 연동
- Jira 문서 및 Notion 블록 파싱
- 테스트 목적, 시나리오, OS·버전·우선순위 메타데이터 자동 생성
- Dry-run, 완료 마커, 템플릿 상태 검증을 통한 기존 문서 보호
- 기능별 화면 경로, 재현 방법, 로그 수집 방법을 정리한 화면 네비게이션
- 설치 및 MCP 연결 방법을 담은 신입 사용자용 스타터 키트
- 파서, 블록 생성, 메타데이터 추출, 보호 로직 단위 테스트

## 팀에 남기고자 한 가치

- 반복적인 테스트 문서 작성 흐름을 자동화 가능한 프로세스로 구조화
- 기존 문서 훼손을 방지하는 검증 장치를 포함해 실무 적용 안정성 고려
- 화면 경로와 테스트 지식을 질문 중심 문서로 바꿔 탐색 가능한 지식으로 정리
- 설치부터 사용까지 이어지는 스타터 키트로 신규 사용자의 진입 과정 지원
- 개인의 작업 요령이 아니라 재사용하고 확장할 수 있는 코드와 문서로 기록

## 인턴 경험을 통해 배운 점

- QA는 기능을 확인하는 일뿐 아니라 사용자 흐름과 시스템 연결 관계를 이해하는 과정이었습니다.
- 반복되는 불편은 개인 요령보다 프로세스와 도구로 구조화할 때 더 오래 활용될 수 있었습니다.
- 업무 자동화에서는 생성 기능만큼 기존 데이터를 보호하고 사용자의 신뢰를 얻는 설계가 중요했습니다.
- 짧은 기간에도 맡은 업무를 충실히 수행하며 작은 개선을 누적하면 팀에 남는 결과물을 만들 수 있었습니다.

## 공개 범위

이 샘플은 설계 방식과 코드 작성 역량을 보여주기 위한 포트폴리오 자료입니다.
실제 사내 자동화 코드 및 운영 문서는 회사 자산과 내부 정보를 보호하기 위해
공개하지 않습니다.
