# [LLM & AI] Gemini Pro 및 LLM 모델 선정을 통한 앱 개발 로직 초안 작성법

경기도일자리재단 미래융합전문교육 바이브코딩 개발자 과정에서는 아이디어를 바로 코드로 옮기기보다, LLM을 활용해 서비스의 목적과 구현 범위를 먼저 정리하는 연습을 했다.

Gogisise는 축산물 시세를 모바일에서 빠르게 확인하는 서비스다. 처음에는 “가격 정보를 보여준다”는 수준의 아이디어였지만, Gemini Pro를 활용해 사용자, 데이터 출처, 화면 흐름, API 역할을 나누며 구현 가능한 MVP로 좁혀 갔다.

## 모델을 고르는 기준

LLM 모델을 선택할 때는 단순히 답변이 자연스러운지보다 개발 과정에서 어떤 역할을 맡길지 먼저 정했다.

- 아이디어 정리: 사용자의 문제와 핵심 기능 후보를 빠르게 확장
- 구조화: FE, BE, Crawler, DB 역할을 분리
- 구현 초안: 컴포넌트, API, 데이터 스키마의 시작점 생성
- 검토: 누락된 예외와 배포 전 확인 항목 점검

이 과정에서 중요한 점은 LLM 답변을 그대로 붙여 넣는 것이 아니라, 프로젝트 맥락에 맞게 줄이고 검증하는 일이었다.

## Gogisise에 적용한 흐름

```text
서비스 아이디어
→ 사용자 문제 정의
→ 핵심 기능 후보 정리
→ 모바일 UI 흐름 작성
→ 데이터 수집과 저장 구조 분리
→ API 응답 형태 초안 작성
→ 배포 전 검증 목록 생성
```

LLM은 생각을 대신하는 도구가 아니라, 놓친 질문을 빠르게 드러내는 도구에 가까웠다.

## 배운 점

앱 개발 로직 초안은 “멋진 문장”보다 “다음 작업으로 이어지는 구조”가 중요하다. 좋은 프롬프트는 결과물을 바로 완성하지 않더라도, 구현자가 어떤 파일을 만들고 어떤 순서로 검증해야 하는지 선명하게 만든다.
